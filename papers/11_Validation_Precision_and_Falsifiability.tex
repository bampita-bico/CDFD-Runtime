\begin{abstract}
\noindent \textbf{Executive synthesis.} CDFD is useful only if it can fail.
This paper defines the validation standard for the runtime series: numerical
sanity checks, finite-value audits, reproducible CLI commands, experiment
selection, precision analysis, and domain-specific falsification. The local
experiments are treated as model diagnostics unless external validation is
available.
\end{abstract}


\paragraph{Greek-symbol convention.}
Unless a manuscript states a tighter equation-local meaning, Greek symbols are local CDFD variables or coefficients, not universal constants. Here $\Phi$ denotes driving flux, $\Psi_s$ denotes the adaptive operating ratio, $\Omega$ denotes a domain or state space, and $\Lambda$ denotes the Life Number where used. The coefficients $\alpha$, $\beta$, and $\gamma$ denote accumulation or reinforcement, relaxation or decay, and diffusion, coupling, or redistribution. The symbols $\delta$ and $\epsilon$ denote perturbation or tolerance scales, while $\eta$, $\lambda$, $\mu$, $\nu$, $\rho$, $\sigma$, $\tau$, and $\phi$ denote local efficiency, rate, baseline, frequency, density or correlation, noise or variance, time-scale, and phase or field terms. Subscripts restrict any coefficient to the named pathway, tissue, domain, or experiment.

\section{Prior CDFD Basis}
This manuscript does not rederive the mathematical core of CDFD. It uses the
Mujjabi Adaptive Operating Ratio and the constrained-vacuum notation introduced
in Part I \cite{MujjabiI2026}, the torus-knot hierarchy and boundary-mode work
from the Part I sequence \cite{MujjabiVI2026,MujjabiIX2026}, the public balance
law developed in the Part I capstone \cite{MujjabiX2026}, the Part I transport
tests \cite{MujjabiXII2026}, and the Life Number and tri-regime biology bridge
from Part II \cite{MujjabiPartII2026}. The runtime papers therefore act as an
execution layer: they keep the mathematics connected to commands, outputs,
falsification tests, and domain-specific limits.


\section{Validation Ladder}
The runtime uses a staged ladder:
\begin{enumerate}
    \item source compiles and imports;
    \item unit tests pass;
    \item CDFL model validates;
    \item simulation outputs are finite;
    \item rerun reproduces the qualitative regime;
    \item parameter sensitivity is documented;
    \item independent data or experiment challenges the claim.
\end{enumerate}

\section{CLI Verification}
The CLI pass added a reproducible command surface. A minimal verification set
is:
\begin{verbatim}
python cdfd.py info
python cdfd.py domains
python cdfd.py diagnostics
python cdfd.py demo origins_of_life \
  --source-scenario mixed_source_surface_trap
python cdfd.py validate examples/heat_flow.cdfl
python cdfd.py run examples/heat_flow.cdfl \
  --out outputs/heat_flow_run.json
\end{verbatim}
The result envelope includes provenance and \texttt{finite\_audit}. Non-finite
values are blockers unless the run is explicitly a boundary-failure test.

\section{Test Evidence}
The focused runtime check recorded:
\begin{verbatim}
python -m pytest -q tests/test_cli_runtime.py \
  tests/test_new_engine_upgrades.py
\end{verbatim}
with 15 passing runtime and native-engine tests. These tests cover CLI runner
behavior, CDFL parsing and execution, Part II diagnostics export,
origins-of-life guardrails, app-key redaction, and selected native engine upgrades.

\section{Precision Analysis}
\texttt{experiments/reports/PRECISION\_ANALYSIS.md} argues that ordinary
float64 hardware is not the limiting factor for these simulations. The dominant
errors are time-step selection, grid resolution, model stiffness, and CODATA
measurement uncertainty for $\chi^*=\alpha^{-1}=137.035999177$. Therefore,
validation focuses on numerical convergence and model controls rather than
on the laptop used to run the experiment.

\section{Experiment Selection}
\texttt{experiments/reports/FINAL\_RELEASE\_EXPERIMENT\_SELECTION.md} is the
current release-facing filter. It selects:
\begin{itemize}
    \item the Mujjabi Vacuum Hysteresis Test as a candidate memory protocol;
    \item the Mujjabi \(n=7\) Knot Stability Test as a weak
    self-stabilization stress test;
    \item the Mujjabi Life Number Boundary Test as a bridge to Part II;
    \item frontier and gigamarathon sweeps as discovery coverage evidence;
    \item \texttt{part\_ii\_runtime\_diagnostics.json} as the CLI-exported
    source-mix and guardrail bundle.
\end{itemize}
It also excludes overloaded adaptive-surface output as support; that run is an
instability boundary.

\section{Domain Falsification}
Each domain needs explicit failure conditions. For example:
\begin{itemize}
    \item OOL: if the proposed $\Lambda$ boundary is indistinguishable from an
    energy-only model, the tri-regime extension adds no value.
    \item Finance-climate: if a directed edge remains after coupling is removed,
    the causal result is an artifact.
    \item Biology/pharmacology: if the $\Psi_s$ proxy does not stratify outcomes
    beyond standard variables, the mapping fails.
    \item Vacuum hysteresis: if residual signatures vanish after thermal and QED
    confounders are controlled, physical vacuum-memory interpretation fails.
\end{itemize}

\section{Conclusion}
Validation is not a final chapter. It is the discipline that must accompany
every paper, every experiment, and every CLI output. The runtime becomes
more useful by becoming more falsifiable.
